# 虚拟桌面输入注入失效 — 根因排查报告

日期：2026-10-02
结论级别：**已实证**（非推测）。所有结论均可由下文脚本复现。

---

## 1. 现象

`XiaoGongZuoTai.exe --input <sid> combo "Ctrl+Shift+Esc 任务管理器"` 之类的命令：

- 主程序日志打印 `cli input: combo ... to session 2`
- `XgtVd2` 侧 HTTP `/input` 返回 `OK`
- **虚拟桌面画面毫无变化**

同类症状：`key`（单键）、`click`（鼠标点击）、`text`（文本）全部无反应。

---

## 2. 根因

**一句话**：RDP ActiveX 宿主窗口被移到了**屏幕外**并且**处于不可见状态**，
在此状态下 **RDP 客户端不会把输入转发到远端会话**，窗口也不参与鼠标命中测试。

### 2.1 代码位置

`src/XgtVd2.cs` 第 162-164 行：

```csharp
host.Size = new System.Drawing.Size(1280, 800);
...
host.Location = new System.Drawing.Point(-30000, -30000);   // ← 屏外
```

窗口扩展样式实测：`exstyle = 0x00090108` → 含 **`WS_EX_LAYERED (0x80000)`**
且 **`WS_EX_TOPMOST (0x8)`**，而代码中**从未调用 `SetLayeredWindowAttributes`**。
`WS_EX_LAYERED` 窗口在未显式设置 alpha 时不可见。

### 2.2 由根因直接导出的两个可观测事实

| 观测项 | 屏外 / alpha=0 | 屏内 / alpha=255 |
|---|---|---|
| `WindowFromPoint` 在窗口中心 | 返回**底层无关窗口** | 返回 `0x00130360 IHWindowClass` |
| `DwmGetWindowAttribute(DWMWA_CLOAKED)` | 0（未被 cloak，是真正的"看不见"） | 0 |

`WindowFromPoint` 的结果证明：**alpha=0 的 layered 窗口鼠标穿透**，
所以任何"移动光标再点击"的注入都会打到别的窗口上。

---

## 3. 实测矩阵

用 Python + ctypes 直接驱动宿主窗口（绕开 XgtVd2 自身逻辑），
以"**读帧图片看画面里到底发生了什么**"作为唯一判据：

| # | 窗口状态 | 注入方式 | 结果 |
|---|---|---|---|
| 1 | 屏内 `(40,40)` + `alpha=255`（真可见） | `SendInput` 鼠标点击 | ✅ **生效** — QQ 从左侧列表打开了"QQ邮箱提醒"会话窗口 |
| 2 | 屏内 + `alpha=0`（不可见） | `SendInput` 键盘 `Ctrl+Alt+End` | ❌ 远端未出现安全界面 |
| 3 | 屏外 + `alpha=0` | `SendInput` 键盘 | ❌ |
| 4 | 屏外 | `PostMessage` → 宿主窗口 | ❌ |
| 5 | 屏外 | `PostMessage` → `IHWindowClass` | ❌ |
| 6 | 屏内 `alpha=255` | `SendInput` + `SetForegroundWindow` + `SetFocus(IH)` | ✅（同 #1，聚焦链路完整时最稳） |

### 3.1 唯一有效组合

```
窗口真正可见（在屏内 + 不透明）
  + SetForegroundWindow(宿主窗口)
  + AttachThreadInput + SetFocus(IHWindowClass)
  + SendInput（键盘 / 鼠标）
```

### 3.2 `IHWindowClass` 的问题（重要）

RDP 客户端内部确实有一个 `IHWindowClass`（类名，标题 `Input Capture Window`），
可通过 `EnumChildWindows` 在宿主窗口的子窗口里找到。**但把消息 PostMessage 给它一样无效**：

- RDP 输入管线**不通过窗口消息**取输入（大概率走 Raw Input / 低级钩子）
- `IHWindowClass` 收 `WM_KEYDOWN` 却不转发；
  **收 `WM_KEYDOWN` 但完全不处理 `WM_CHAR`**（无 `WM_IME_*`），
  所以"用 `WM_CHAR` 输入文本"这条路必然失败

> 本仓库 2026-10-02 09:59 的那次"修复"（`XgtVd2.cs.bak_20261002_inputfix`）
> 就是走"PostMessage 到 IHWindowClass"这条路 —— **方向错误，已被本报告证伪**。

## 4. 技术退化路径（本次最重要的教训）

| 时期 | 实现 | 输入机制 | 是否有效 |
|---|---|---|---|
| 早期 | `src/xgt/XgtCapture.cs` | `SetCursorPos` + `SendInput`（`HandleInput`，第 242 行起） | ✅ 有效 |
| 后期 | `src/XgtVd2.cs` | `PostMessage` → 屏外宿主窗口 | ❌ 无效 |

**这是一次静默的功能退化。** 之所以长期没被发现，是因为：

1. **画面能抓**（`PrintWindow` 抓的是 RDP 持久位图缓存，屏外一样能抓到内容）
2. **命令有回执**（HTTP 返回 `OK`、日志打印成功）
3. **返回码漂亮**（`PostMessage` 对有效 HWND 一律返回成功，不管内容）

→ **"有回执" ≠ "有效果"。验收必须看最终语义结果，不能看中间层的返回码。**

## 5. 修复方向

### 方案 A（最小改动，已验证有效）：让宿主窗口保持真正可见

若要保留"后台隐藏窗口 + HTTP 抓帧"的形态，需要放弃"隐藏"：

```
连接成功后：
  SetWindowPos(host, HWND_TOP, 0, 0, W, H, SWP_SHOWWINDOW)
  SetLayeredWindowAttributes(host, 0, 255, LWA_ALPHA)   // 不透明
  — 用户会看到虚拟桌面窗口（就是普通 RDP 窗口的外观）

注入时：
  SetForegroundWindow(host)
  AttachThreadInput(curTid, ihTid, true); SetFocus(ihHwnd); AttachThreadInput(..., false)
  SendInput(...)      // 键盘 + 鼠标
```

代价：宿主窗口必须对用户可见 —— 与"后台常驻"的产品意图冲突。

### 方案 B（正交，未验证）：绕开 RDP 输入管线

`src/XgtHelper.cs` 是 **SYSTEM 常驻守护**。SYSTEM 进程可以：

- `WTSQueryUserToken(2)` + `CreateProcessAsUser` → 直接在会话 2 里启动进程
- 或者把注入请求交给一个**运行在会话 2 内部**的代理进程

完全绕开 RDP 客户端，不受窗口可见性影响。**这是更彻底的解法**，
代价是要新增/接通会话内代理。

### 方案 C：临时移入（折中）

平时窗口在屏外；注入前 `SetWindowPos` 移到屏内、`SetForegroundWindow`、注入、移回。
缺点是每次注入要移动窗口，且需等待 RDP 恢复渲染，有闪烁与延迟，稳定性未验证。

## 6. 方法学：不要用帧哈希判断输入是否生效

实测：在**不做任何输入**的情况下，RDP 画面**每秒都会自然刷新**
（连续 8 次采样得到 8 个互不相同的 md5）。

因此：

> **「帧 md5 变了」不能作为输入生效的证据**，只能用**语义判据**
> —— 把帧读出来看图片里到底发生了什么。

本次排查中途曾两次因用 md5 判断而得错结论：
先误判"输入完全无效"，后又误判"alpha=0 也有效"。

## 8. 实施方案 B（已完成，2026-10-02）

**思路**：不要试图让 RDP 客户端转发输入，而是**在目标会话内部**注入 —— 会话内进程的
`SendInput` 直接进该会话的输入队列，与 RDP 输入管线完全无关。

### 8.1 组件

| 组件 | 位置 | 作用 |
|---|---|---|
| `XgtAgent.exe` | `C:\Users\Public\Xgt\XgtAgent.exe` | 运行在虚拟桌面会话**内部**的代理：输入注入 + 抓屏 + 状态查询 |
| 自启动项 | `HKCU\...\Run` 值 `XgtAgent` | 子会话登录时自动拉起代理（零提权，用户级可写） |
| `src/XgtAgent.cs` | 本仓库 | 源码 |

代理源码里的关键约束：

```csharp
if (sid <= 1 && !_force) { Log("console session -> exit (by design)"); return 0; }
```

console 会话与子会话**共用同一个 loopback 端口**，谁先占谁得；因此代理默认只在
`SessionId > 1` 时启动，避免与 console 抢端口。另外若端口被占也会自行退出。

### 8.2 代理接口（HTTP/1.0，响应后关闭连接）

```
GET /ping                              -> pong sid=<n>
GET /info                              -> sid=<n> screen=<w>x<h> fg=<hwnd> title=<t>
GET /frame                             -> JPEG 该会话桌面全屏
GET /shot?x=&y=&w=&h=                  -> JPEG 区域
GET /input?cmd=click|dbl|right|down|up|rightdown|rightup|move|wheel&x=&y=[&d=]
GET /input?cmd=key|keydown|keyup&k=<vk>
GET /input?cmd=combo&k=17,16,27        -> 顺序按下，逆序抬起
GET /input?cmd=text&t=<urlencoded>     -> KEYEVENTF_UNICODE 逐字符
任意 input 可加 &pm=1                  -> 额外向当前前台窗口 PostMessage（兼容 Raw Input 应用）
```

### 8.3 主程序接入

`src/Main.cs` 新增 `InputAgent` 工具类，**优先走会话内代理，探测不到时回退 RDP 助手的 `/input`**：

```csharp
internal static class InputAgent
{
    public const int Port = 17790;
    public static bool Available();      // 250ms TCP 探测，结果缓存 5 秒
    public static int  Pick(int fallbackPort);
    public static string WheelCmd(int port);   // 代理叫 wheel，RDP 助手叫 scroll
}
```

改造点：`SendInputCmd` / `SendKeyCmd` / 滚轮 / 文本输入 / CLI `--input`（共 6 处），
全部由 `viewPort` 改为 `InputAgent.Pick(viewPort)`。

### 8.4 验收证据（语义判据）

| 步骤 | 命令 | 结果 |
|---|---|---|
| 代理存活 | `GET /ping` @17790 | `pong sid=2` |
| 会话信息 | `GET /info` | `sid=2 screen=1280x800` |

| 主程序接入 | `XiaoGongZuoTai.exe --input 2 key 91` | 返回 `OK cmd=key`（代理格式），开始菜单弹出 |

### 8.5 为什么这是"回退"而不是"新发明"

仓库早期的 `src/xgt/XgtCapture.cs` 走的正是这条路（`XgtHelper`(SYSTEM) 用
`CreateProcessAsUser` 把 `XgtCapture.exe` 注入目标会话，会话内用 `SendInput`）。
后来换成 `XgtVd2`（RDP ActiveX + `PostMessage`）后输入就废了。

本方案的通道形态并非新发明 —— 仓库早期的 `src/xgt/XgtCapture.cs` 就是会话内 `SendInput`。
本次新增的只是**把 SYSTEM 计划任务换成用户级自启动**（零提权）：
**不需要管理员，不需要计划任务**。

> **旁证（仅印证形态可行，代码零复用，勿误读为依赖）**
> 本机另一项目（`zangai-tycoon/tools/vd_agent.cs`，与"小工作台"无关）早在用同一形态
> 「用户级自启动 + 会话内代理 + loopback」，其日志显示每次虚拟桌面重建都被自动拉起
> （`agent start sid=8 … 22`）。这只能说明**该形态在本机确实跑得通**，
> 不构成对本方案的任何代码依赖。
>
> 本次的 `XgtAgent` 是独立重写：独立端口（17790 vs 17800）、独立自启动项、独立实现。
> 源码级核验：`XgtAgent.cs` 中检索 `vd_agent` / `17800` / `zangai` / `Godot` **零命中**。
> 该旁证**可随时移除**，不影响 `XgtAgent` 的任何功能。
